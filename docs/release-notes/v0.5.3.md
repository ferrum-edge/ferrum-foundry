# Ferrum Foundry v0.5.3

> Foundry v0.5.3 pairs with published Ferrum Edge v0.9.14 and canonical
> `contracts-edge-0.9.14`. Hosted qualification evidence is recorded in the
> [compatibility record](https://github.com/ferrum-edge/ferrum-foundry/blob/v0.5.3/docs/compatibility.json);
> the published image digest is listed under Docker below.

This release moves the development and CI pin to published Ferrum Edge
v0.9.14, adopts the existing canonical contract scope at
`contracts-edge-0.9.14`, shows the data-plane backend egress attestation that
Edge v0.9.14 adds to `GET /cluster`, and ships the source merged since v0.5.2.
It changes no runtime profile or authority tier.

### Changes since v0.5.2

- **Data-plane backend egress attestation on the Cluster page.** On a control
  plane, Edge v0.9.14 reports each data plane's self-reported backend egress
  policy on `GET /cluster` (`backend_egress_policy_attestation`,
  `backend_egress_policy`) and a cluster-wide
  `data_plane_backend_egress_policy` aggregate (ferrum-edge#6020). Each data
  plane row shows its reported mode, whether it is public-only, or that its
  policy is unknown. The control-plane card summarizes reporting and unknown
  counts, the weakest reported mode and whether every connected data plane is
  public-only. The page states that these are self-reports, not host
  attestation, and that a disconnected data plane serving cached configuration
  is not listed. A response without the fields renders as before. Foundry
  still does not read `GET /backend-egress-policy`, whose new optional
  `data_plane_attestation` object is additive within `schema_version: 2`.
- **One row per Subscribe stream.** Edge v0.9.14 lists one data-plane entry per
  live ConfigSync Subscribe stream, so several entries can share a `node_id`.
  The Cluster page now keys each stream separately instead of by `node_id`, so
  no stream is collapsed or hidden.
- **Edge v0.9.14 deployment mutation outcomes.** A conditional deployment
  mutation's store failure now reports `durable: "not_started"` before the
  mutation transaction and `durable: "not_committed"` inside its rolled-back
  transaction; only an unconfirmed commit still reports `"unknown"`
  (ferrum-edge#6021). Foundry issues no deployment mutation, and the
  browser-facing BFF keeps refusing `GET /deployment-snapshot` for every method
  and role with `403 FERRUM_BFF_CREDENTIAL_READ_DENIED` before capacity
  admission, JWT signing or upstream fetch.
- **Security pin (#558).** The development-only transitive `shell-quote`
  dependency is pinned to 1.12.0 through an npm `overrides` entry, fixing
  GHSA-pqg4-j6r4-53mv. No runtime dependency changes.
- **Licensing (#559).** Ferrum Edge LLC is named as the copyright holder and
  commercial licensor in `LICENSE` and `LICENSE-COMMERCIAL.md`.
- **Pins and contracts.** Starter, development command and current record use
  the same published Edge digest. Package and lockfile root versions are 0.5.3.
  The same 18 contract files are taken byte-exact from canonical commit
  `ddbdd845733b7046c4393ac951011dafb774db33` after main Validate contracts run
  `37755967635` succeeded. Only the vocabularies' Edge provenance and OpenAPI
  digest and the complete canonical invalid expectations change; the latter
  adds the backend-egress-policy data-plane attestation negatives without
  Foundry adopting those schemas. All 82 plugin entries, provisioning values,
  manifest schema and all 12 fixtures are unchanged. Shared status remains
  EXISTING/implemented at Alloy owner 81cbb; Alloy stays unpublished.
- **Plugin sensitivity and guided schemas.** Edge's registered plugin set and
  `PluginConfigBase` are unchanged, and its projection source is
  byte-identical to v0.9.13, so the sensitivity table is unchanged and its
  provenance names the v0.9.14 source. All five guided schema blocks are
  byte-identical at v0.9.14, so every pinned hash, descriptor, template,
  secret-handling rule and unmodelled-value behavior is unchanged.
  [Schema provenance](https://github.com/ferrum-edge/ferrum-foundry/blob/v0.5.3/docs/plugin-schemas.md#v053-schema-review)
  records the review.

### Known limits

This release adds no backend egress policy reader, egress publication
decision, conditional backup or restore, native deployment workflow, recovery
journal, capability or browser retention guarantee. The Cluster page's egress
attestation reflects only the control plane Foundry is connected to and only
data planes connected when it was read. #547 account-level immutability
decisions remain pending.

No advisory closure or unrelated upstream approval is implied. Existing
best-effort/unqualified modes (including `cp`, where the new Cluster page
fields appear), eBPF variants, real-gateway scale limits and browser limits
remain unchanged.

### Publication and deployment

Deploy Foundry v0.5.3 against the paired Ferrum Edge v0.9.14 image,
`ferrumedge/ferrum-edge@sha256:15442f1b1d1758023fe871fe57be50f19caf34bbe6c499a6812f4ffd0da5e3f8`.
In production, pin the released Foundry multi-architecture index digest listed
under Docker below rather than a mutable tag. Edge v0.9.14 raises the
ConfigSync protocol revision to 3, so its control and data planes must run the
same build. The demo bootstrap's `:main` remains the development channel.
Versioned v0.5.2, v0.5.1, v0.5.0 and v0.4.0 notes and records remain
byte-for-byte unchanged. Their source, image and CI evidence are historical;
published version tags must never move.
