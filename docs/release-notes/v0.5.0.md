# Ferrum Foundry v0.5.0

> **Published and qualified 2026-10-04.** Foundry v0.5.0 pairs with Ferrum
> Edge v0.9.11. Root-verified hosted qualification, release-run and registry
> evidence are recorded in [the compatibility record](../compatibility.md) and
> its [immutable v0.5.0 snapshot](v0.5.0.compatibility.json).

This release pairs Foundry v0.5.0 with the verified published **Ferrum Edge
v0.9.11** distribution. It adds authenticated Alloy service-manifest preview
and tightens the BFF, backup export, deployment and release boundaries. Changes
are the actual main changes since
[v0.4.0](https://github.com/ferrum-edge/ferrum-foundry/releases/tag/v0.4.0);
the release comparison is `git log v0.4.0..v0.5.0`.

### Highlights since v0.4.0

- **Alloy service-manifest preview (#540).** Settings previews the shared v1
  JSON data model through an authenticated, namespace-authorized BFF route.
  Desired proxy, upstream and plugin fields are bounded, TLS paths are
  redacted, and namespace switches clear the draft. Preview applies nothing,
  fetches no producer or local file, and installs no MCP tools, auth policy or
  API specification. The pin now adopts published `contracts-edge-0.9.11` at
  `390edbd5b2485af0988e02f7827fde778d76ae0a`, with all manifest fixtures and
  canonical invalid expectations. Shared manifest/report status is
  EXISTING/implemented at qualified Alloy owner 81cbb; validation fields and
  fixtures are unchanged. Published descriptions retain their historical
  preparation wording. Diagnostic presentation remains future work under the
  existing ADR, and Alloy remains unpublished.
- **Sensitive reads and backup state (#543).** The browser proxy refuses
  consumer verification on the canonical forwarded pathname before signing
  or contacting Edge, including encoded paths and HEAD. Backup export returns
  only completion counts to mutation state, uses `gcTime: 0`, revokes download
  URLs, and keeps namespace and gateway bindings throughout the operation.
  Failures retain fixed diagnostics and status without archival credential
  excerpts or request metadata.
- **Namespace cascade confirmation (#538).** Exactly one literal
  `confirm=<namespace-name>` must echo the decoded target. Encoded values,
  duplicates, mismatches and ambiguous queries are refused before forwarding.
  This acknowledgment does not prove a prior occupancy result or single use.
- **Bounded reads (#532).** Long polls, backup downloads and namespace-scoped
  listing share global and per-principal admission limits. A full pool returns
  `429`, and apply-status polling respects `Retry-After`. Scoped registry reads
  stop when all grants are found or fail explicitly at their scan budget;
  identical in-flight reads share work. Gateway connections and starter API
  concurrency are bounded.
- **Deployment and secrets (#527, #529, #536).** Production remote admin
  connections require HTTPS and verified TLS unless the explicit disposable
  stack override is set. Trusted-proxy identity headers cannot collide. OIDC
  templates require an operator-owned session encryption secret.
- **Release integrity and runtime (#533, #537).** Release version tags remain
  tied to one source commit and image digest; the workflow compares before
  publishing and records planned digests for partial-publication diagnosis.
  A stranded half-release requires the next patch version. Runtime images
  return to pinned distroless Node 24 as UID/GID `65532:65532`, without shells
  or package managers. Dynamic admin identifiers are encoded as single path
  segments (#528).

The release includes main's fixes for GHSA-27j6-vr5h-8p6v (admin transport),
GHSA-74cv-h27v-866v (identity headers), GHSA-hjw6-685j-p5hw (public OIDC template
key), GHSA-jw5q-qmrj-m87g and GHSA-37q7-fc8p-hchr (read/list admission),
GHSA-64c9-hw76-jqmh (identifier paths), and GHSA-rw8r-hrr2-vpc2 (release tag
reassignment).

Edge v0.9.11 retains the MCP charset and batch inspection fixes from v0.9.10.
It does not fix [Edge #6008](https://github.com/ferrum-edge/ferrum-edge/issues/6008)
(SOAP pre-auth body collection total deadlines) or
[Edge #6009](https://github.com/ferrum-edge/ferrum-edge/issues/6009)
(native HTTP/3 early-body retained-request admission). This release is not a
claim that all upstream security work is fixed.

Real-gateway coverage remains tens of resources across two namespaces.
Synthetic request budgets reach 50,000 records; browser latency and concurrent
operator scale are not qualified. Only Chromium is in the browser gate.
The canonical tag and shared v1 status are published, and the Foundry pairing
passed hosted qualification. Remaining coordinated adoption stays
tracked in ferrum-alloy#27/#28; it grants no Alloy crate publishing approval.

### Install

Use the Foundry digest recorded in `docs/compatibility.json` and the verified
Edge image digest in the pairing table above.

Follow [Getting started](../getting-started.md) and [Deployment](../deployment.md)
with the release starter. The starter's default `:main` is the development
channel. The recorded v0.5.0 image source, index, platform manifests, revision
labels and hosted CI evidence are specific to this release; v0.4.0 facts do
not substitute for them.

### Upgrading from v0.4.0

Take a gateway backup per namespace and protect it as a secret-bearing archive.
Follow Edge's [v0.9.11 upgrade guide](https://github.com/ferrum-edge/ferrum-edge/blob/v0.9.11/docs/upgrade_guide.md)
first, then replace the Foundry image with the actual v0.5.0 release digest.
Edge owns its buildout database procedure; preserve the old database for
rollback and follow its logical export and fresh-datastore guidance. Foundry
has no database or migrations. Reload browser tabs, confirm
`GET /api/health/ready` reports `0.5.0` and a reachable gateway, and verify
representative authorized reads and guarded writes.

Production deployments using a remote plaintext admin URL must configure HTTPS.
Remote HTTPS requires `FERRUM_TLS_VERIFY=true` and a suitable
`FERRUM_TLS_CA_PATH` when using a private CA. The explicit
`FERRUM_ALLOW_INSECURE_ADMIN_HTTP=true` exception is for disposable stacks;
sharing Edge's env file also enables that exception in Foundry. Update the
starter configuration with this release and review identity header names for
collisions.

If an OIDC configuration came from the old public template, rotate
`session.encryption_secret` now. Do not retain the public key in
`session.encryption_secret_previous`. Read admission settings have bounded
defaults; size them for the instance without changing role or namespace grants.

### Rolling back

Redeploy the previous immutable Foundry digest from the preserved v0.4.0
record, paired with its recorded Edge v0.9.10 release. A Foundry rollback does
not undo configuration written through the newer UI. Use Edge's own rollback
guidance, the retained old gateway database and protected namespace backups.
Do not move a version tag to perform a rollback.
