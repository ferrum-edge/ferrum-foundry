# Ferrum Foundry v0.5.4

> Foundry v0.5.4 is a security and fix patch release. It pairs with the same
> published Ferrum Edge v0.9.14 and canonical `contracts-edge-0.9.14` as
> v0.5.3. Hosted qualification evidence is recorded in the
> [compatibility record](https://github.com/ferrum-edge/ferrum-foundry/blob/v0.5.4/docs/compatibility.json);
> the published image digest is listed under Docker below.

This release bounds what a namespace-scoped session can reach through the BFF
and ships the source merged since v0.5.3. The Edge pin, platform digests,
contract pin, plugin sensitivity table and guided schema hashes are unchanged
from v0.5.3. It changes no runtime profile or authority tier, but it narrows
what a session with namespace grants may do; read [Upgrading](#upgrading)
before deploying it.

### Changes since v0.5.3

- **Namespace route ceiling (#562).** A session with namespace grants may now
  reach only the gateway admin routes its namespace grant actually scopes,
  plus a small fleet-wide allowlist. Every other route, including any route
  Foundry has not classified, is refused by the BFF with
  `403 Namespace access denied` before a JWT is signed or the gateway is
  contacted. HEAD is classified like GET. The credential-read denials and the
  unsafe-path `400` run first and keep their documented codes.
- **Health summary for scoped sessions.** `/health` and `/status` answer a
  namespace-scoped session with only `status`, `timestamp`, `mode`,
  `admin_writes_enabled` and `ready`, the facts the capability model reads.
  Upstream length, validator and range headers are dropped.
- **Fleet TLS is read and validate only for scoped sessions.** They may read
  fleet TLS material and call the stateless validate route, but may no longer
  create, replace, rotate, renew, finalize or delete it.
- **Navigation follows the ceiling.** For a namespace-scoped session the
  sidebar hides Dashboard, Metrics, Cluster and Mesh, which the BFF now
  refuses. The Audit Log stays and lists the rows of the session's own
  namespaces.
- **Publication record (#561).** The verified v0.5.3 publication evidence is
  recorded, and the immutable v0.5.3 record is preserved byte for byte.
- **Version.** Package and lockfile root versions are 0.5.4.

### Upgrading

**Breaking for namespace-scoped principals.** A principal with namespace
grants is a trusted-proxy identity whose namespaces header names one or more
namespaces, or a static-mode session whose `FERRUM_JWT_NAMESPACES` lists exact
names. From v0.5.4 such a session:

- gets only the health summary above from `/health` and `/status`, never the
  detailed view;
- can read and validate fleet TLS material but cannot create, replace, rotate,
  renew, finalize or delete it;
- may use only known namespace-scoped admin routes, each naming one of its
  grants in `X-Ferrum-Namespace`, plus the documented fleet-wide allowlist;
- cannot use fleet-global routes such as `/cluster`, `/overload` or mesh
  egress scope (`/mesh/egress-scope`), which are denied with `403`.

Unrestricted principals are unchanged: a trusted-proxy `admin` asserted
without a namespaces header, or static mode with `FERRUM_JWT_NAMESPACES='*'`.
If an operator needs the Cluster, Mesh or Metrics surfaces, or fleet TLS
writes, give that identity an unrestricted admin mapping. The starter maps
every group, `ferrum-admins` included, to a namespace, so every starter user
is scoped. See
[Namespace route ceiling](https://github.com/ferrum-edge/ferrum-foundry/blob/v0.5.4/docs/authentication.md#namespace-route-ceiling)
in `docs/authentication.md` for the full route classes.

Edge records fleet-wide actions under its default `ferrum` namespace, so a
session granted `ferrum` reads those audit rows. Grant `ferrum` only to
identities that may see fleet-wide audit.

### Security

This release hardens namespace-scoped authorization in the BFF. Deployments
that rely on namespace grants to separate tenants or teams should upgrade.
The fix is enforced in the BFF; Ferrum Edge remains an enforcement point and
no Edge upgrade is required.

### Known limits

The ceiling is enforced by Foundry's BFF only. Clients that reach the Ferrum
Edge admin API directly are governed by Edge's own authorization. A new Edge
admin route is refused to scoped sessions until Foundry classifies it. #547
account-level immutability decisions remain pending.

No advisory closure or unrelated upstream approval is implied. Existing
best-effort/unqualified modes, eBPF variants, real-gateway scale limits and
browser limits remain unchanged.
