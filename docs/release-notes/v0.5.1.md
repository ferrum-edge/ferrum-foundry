### Source changes

- The browser-facing BFF explicitly refuses the secret-complete
  `/deployment-snapshot` read for every method and role with
  `403 FERRUM_BFF_CREDENTIAL_READ_DENIED`, after authentication and before
  capacity admission, JWT signing or upstream fetch. Encoded route components,
  an optional trailing slash and queries cannot bypass the normalized pathname
  check. Ordinary masked reads and ephemeral backup downloads remain supported.
- Starter, development command and current record use the same published Edge
  digest. Package and lockfile root versions are 0.5.1; dependency graph and
  Node floors are unchanged.
- The same 18 contract files are downloaded byte-exact from canonical commit
  `31f0a21d707795be293d15837c2f77c3d84219d8`, published as release
  `403772929` at 2026-10-05 13:58:38 UTC after main Validate contracts run
  `37320780987` succeeded. Manifest schema and all 12 fixtures are unchanged.
  Complete canonical invalid expectations include the new deployment entries,
  without adopting their schemas or runtime profile. Shared status remains
  EXISTING/implemented at Alloy owner 81cbb; Alloy stays unpublished.
- Sensitivity provenance names the published Edge source after table review
  and byte equality with c764. Static review of all five guided components is
  complete from verified hosted run `37336969590`, attempt 1, artifact
  `11356821423`, source `0dc21a387367059785c6fbea8c7ced5a55e2af70` and tested
  merge `632a24eb7c5220fd06a6e9fd85d5b5b11308b898`. The reviewed schema ref
  adopts the published Edge source; all five hashes, descriptors, catalog,
  templates, secret handling and unmodelled-value preservation are unchanged.
  [Schema provenance](../plugin-schemas.md#v051-hosted-schema-adoption) records
  verified archive/export hashes and review limits. The previous failed
  producer remains historical schema evidence only.

### Limits and pending work

This pin adoption adds no conditional restore, native deployment workflow,
recovery journal, capability or browser retention guarantee. Existing initial
untagged-write fallback and post-412 refusal remain unchanged; Foundry #542/#544
owner approval and #547 account-level immutability decisions are pending.
The deployment-snapshot refusal does not authorize browser retention of its
original evidence.

No advisory closure or unrelated upstream approval is implied. Edge #6011 is
excluded from v0.9.12. Existing best-effort/unqualified modes, eBPF variants,
real-gateway scale limits and browser limits remain unchanged.

### Publication and deployment

GitHub release `403984368` has no standalone downloadable assets; the published
container image is the distribution. Both registries name the same final index.
Native architecture logs bind `SOURCE_REVISION` and the emitted build indexes
to the tag source. The manifest job validates exactly `linux/amd64` and
`linux/arm64` and compares version-tag identity before and after publication.
Build indexes include image and attestation manifests; they are distinct from
image manifest/config digests. Buildx requested SBOM and `mode=max` provenance,
and the native logs record their generation. Anonymous GHCR access, independent
cryptographic attestation verification and account-level registry immutability
are not claimed.

Pin the actual multi-architecture index for deployments:

```bash
docker pull ferrumedge/ferrum-foundry@sha256:52c76c58958ed20df96c35bd943a500eb00f5a5eb540263dd7dd4e40717f30df
```

The starter's default `:main` remains the development channel. Versioned v0.5.0
and v0.4.0 notes and records remain byte-for-byte unchanged. Their source, image
and CI evidence are historical; published version tags must never move.
