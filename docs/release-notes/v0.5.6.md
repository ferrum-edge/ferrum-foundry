# Ferrum Foundry v0.5.6

> Foundry v0.5.6 pairs with published Ferrum Edge v0.9.20 and canonical
> `contracts-edge-0.9.20`. Hosted qualification evidence is recorded in the
> [compatibility record](https://github.com/ferrum-edge/ferrum-foundry/blob/v0.5.6/docs/compatibility.json);
> the published image digest is listed under Docker below.

This release moves the development and CI pin from Ferrum Edge v0.9.15 to
published v0.9.20, adopts `contracts-edge-0.9.20`, and aligns Foundry's
plugin templates, guided editors, sensitivity table and `mcp_gateway` mode
handling with the stricter v0.9.19 and v0.9.20 admin contract. It also
collects the security hardening, deployment-starter and concurrent-edit fixes
merged since v0.5.5. Several of them change BFF and starter defaults; read
[Upgrading](#upgrading) before deploying.

The pairing depends on ferrum-edge#5661 resource ETag/If-Match handling,
ferrum-edge#5726 proxy-scoped plugin configuration filtering, and
ferrum-edge#6744, the `expected_proxy_ids` association precondition that

### Edge v0.9.20 pairing

- **Pin.** Starter, development command and current record use the published
  Edge v0.9.20 digest. Package and lockfile root versions are 0.5.6.
- **Contracts.** The same 18 files are taken byte-exact from
  `contracts-edge-0.9.20`. The plugin catalog keeps its 82 plugins;
  `ai_token_metrics` moves from priority 4100 to 4070, which
  `PLUGIN_PRIORITY` follows.
- **Templates.** Every plugin config is closed in v0.9.19+, and `opa` refuses
  a cleartext host off loopback, so the `opa` template names an `https://`
  OPA host. The other templates keep their v0.9.15 outcomes; the
  `kafka_logging` refusal now names `FERRUM_KAFKA_ALLOWED_BROKERS`.
- **Guided editors.** `rate_limiting` adds `limit_by: service` and
  `max_state_entries`; `cors` adds `allow_private_network` and enforces the
  128-entry bound on its method and header lists; `key_auth` hands an ordered
  list of key locations to the JSON editor instead of flattening it.
- **Secret handling.** The plugin sensitivity table follows Edge's v0.9.20
  projection: `request_transformer` and `mesh_route_dispatch` rule values,
  `response_mock` and `fault_injection` match values, `waf` exemption header
  values and `ws_logging` `custom_headers` are secret, and `ldap_auth`
  `failover_ldap_urls` is an endpoint, so a failed write no longer echoes them.
- **`mcp_gateway`.** The prompt and resource policy keys join the
  aggregate-only keys the editor strips in `transparent_proxy` mode.
- **Demo data.** Seeded API keys meet v0.9.19+'s 16-character floor.
- **Qualification gates.** The **Starter Production Profile** job, which runs
  the starter's production profile (TLS nginx and oauth2-proxy) against a mock
  OIDC provider, joins the jobs a release's hosted qualification must pass.

### Security

- **Plugin trigger redaction.** A plugin configuration's execution `trigger`
  is redacted like its `config`: every `header`, `query` and `cookie`
  comparison operand is treated as secret by failed-write redaction and shown
  as `[redacted]` in the conflict dialog, following Ferrum Edge's trigger
  projection (ferrum-edge#7054), and a non-admin session's placeholder at a
  masked trigger operand blocks the save before anything is sent (#737).
- **Published example secrets are refused.** The BFF refuses to start when
  `FERRUM_JWT_SECRET`, `FERRUM_TRUSTED_PROXY_SECRET` or
  `FERRUM_BFF_AUTH_TOKEN` still holds the starter's `replace-me-...`
  placeholder, and under `NODE_ENV=production` also the documented development
  values
  ([GHSA-hpqf-v945-35qp](https://github.com/ferrum-edge/ferrum-foundry/security/advisories/GHSA-hpqf-v945-35qp)).
- **Per-principal upload share.** One authenticated subject can no longer hold
  every upload permit (`FERRUM_MAX_UPLOADS_PER_PRINCIPAL`,
  `FERRUM_MAX_LARGE_UPLOADS_PER_PRINCIPAL`; GHSA-733w-pmhj-7r6j).
- **Deployment starter.** oauth2-proxy moves from v7.7.1 to v7.15.6 and nginx
  to 1.31.8 mainline, both pinned by tag and digest and watched by Dependabot.
  nginx sets every forwarded header oauth2-proxy reads from its own values,
  including on the `/oauth2/auth` subrequest (GHSA-q866-mwp4-hgw3), sends its
  own `X-Request-Id`, and clears client-supplied identity and redirect headers
  toward Foundry. oauth2-proxy uses PKCE (S256) and trusts forwarded headers
  only from the starter's own Compose subnet.
- **BFF hardening.** Failed authentication is throttled per address (#588);
  `Strict-Transport-Security` is sent wherever Secure cookies are on (#589);
  the BFF emits no CORS allow headers in any environment (#590);
  unauthenticated health callers get only the verdict (#592); `style-src`
  uses a per-response nonce instead of `'unsafe-inline'` (#594); proxied
  gateway responses are confined to API media types with `nosniff` and a
  sandbox CSP (#601); and API responses always carry
  `cache-control: no-store` (#607).
- **Namespace-scoped sessions.** The BFF's namespace route ceiling follows
  Ferrum Edge's limit on admin JWTs that carry an `ns` claim
  (ferrum-edge#6093): TLS routes and `GET /config/apply-status` are refused
  before signing, scoped health and settings-status answers are reduced to
  the session's tenant, and `PUT /api/settings` is refused (#565). The UI
  withholds the fleet-wide Metrics, TLS and Cluster views from such a session.
- **More redaction.** Inline backend TLS material is secret in refused writes
  and the stale-write dialog (#612), and the editors recognise the backend TLS
  private keys and the certificate, private-key and path sensitivity classes
  that Ferrum Edge `main` masks (#704, #718).
- **Denial of service and dependencies.** Two quadratic regular expressions
  (the namespace description trim and the manifest preview's trailing-slash
  strip) are replaced by linear scans. Transitive `seroval`, `glob` and
  `minimatch` advisories are fixed, and CI gates on moderate production
  advisories (#593).
- **Release workflow.** The publishing jobs run in the protected `release`
  environment, so its reviewers approve a release before anything is pushed
  (#684).

### Concurrent edits

- Plugin updates and deletes send the membership the page showed as
  `expected_proxy_ids`; a proxy attached since is refused with a "membership
  changed" error instead of being silently detached (#630).
- Deleting a plugin configuration is one conditional `DELETE` (#609); a
  plugin create that does not converge is kept and reported rather than
  deleted (#608); failed group scope and membership changes are no longer half
  rolled back (#610, #618); and a detail-page delete compares the fields a
  save leaves out (#602).
- Revoking a single consumer credential is conditional on the consumer `ETag`
  of the list the operator selected from (#703).
- Committed-but-not-live `503` answers are reported as the save, create,
  delete, rename or import they are (#674, #637, #575), and "outcome unknown"
  spec imports, ACME orders and restores stay latched across navigation until
  resolved.
- Upstream saves keep every operator-writable subset field and omit the
  mesh-projected `traffic_policy` fields, edit baselines reduce subsets the
  same way, and a new drift check compares that field list with the pinned
  Edge spec (#717, #725).
- A write Edge stores in a namespace this gateway does not route
  (`X-Ferrum-Namespace-Unserved`) shows a warning instead of a plain success
  (#708).

### Readiness for Ferrum Edge `main`

- A scheduled **Edge Main Drift** workflow checks Foundry weekly against the
  signed Edge `main` image and reports findings in one tracking issue; it is
  never a required check.
- Templates and the `mcp_gateway` editor drop the compatibility spellings Edge
  `main` removes (#702, #706), the proxy form no longer sends
  `pool_max_requests_per_connection` (#701), and the `load_testing` and
  `mtls_auth` templates are admitted once their documented field is filled in
  (#707).
- The Status page shows Edge `main`'s MongoDB mTLS DNS admission fence
  (#727), and the Settings connection test reads Edge's structured `503`
  health answer for a gateway that is starting, degraded, unavailable or
  draining (#724).
- The Alloy service-manifest preview is requalified against Alloy `main`
  (#719, #723).

### Other fixes

The proxy form sends only the settings Edge reads for the selected backend
scheme (#655); the browser session is one explicit state machine (#656); the
Plugins list shows Edge's built-in priorities again (#673); stored consumer
credentials are labelled by type (#676); the fallback namespace field no
longer switches scope on every keystroke (#677); service-discovery names and
ports are validated for every provider (#678); the `mcp_gateway` editor keeps
the JSON under the cursor and its stashed tool policies (#679); failed reads
use one shared notice (#680); backup and restore deadlines cover the BFF's
budgets (#633); `/api/health/ready` requires a valid gateway health snapshot
(#634); a changing namespace registry is no longer reported as a smaller
complete list (#638); and toasts and icon buttons are accessible (#683).
Unused components and dependencies are removed (#682). The
[changelog](https://github.com/ferrum-edge/ferrum-foundry/blob/v0.5.6/CHANGELOG.md)
lists every change.

### Upgrading

**Upgrade Ferrum Edge.** Before upgrading Edge from v0.9.15, read its
[Upgrading to 0.9.17](https://github.com/ferrum-edge/ferrum-edge/blob/v0.9.20/docs/upgrade_guide.md#upgrading-to-0917),
[Upgrading to 0.9.19](https://github.com/ferrum-edge/ferrum-edge/blob/v0.9.20/docs/upgrade_guide.md#upgrading-to-0919)
and
[Upgrading to 0.9.20](https://github.com/ferrum-edge/ferrum-edge/blob/v0.9.20/docs/upgrade_guide.md#upgrading-to-0920)
guides; many changes are breaking. Those that affect what you configure
through Foundry:

- **Plugin configs.** Remove unknown keys at any depth, and set
  `allow_plaintext: true` or move to `https://` for an `opa`,
  `serverless_function`, `otel_tracing` or `workload_metrics` endpoint that is
  cleartext off loopback. Edge refuses to save such a config unchanged.
- **Consumer credentials.** Rotate `keyauth` keys shorter than 16
  non-whitespace characters and `jwt` secrets shorter than 32, and make every
  `jwt`, `keyauth`, `basicauth` and `mtls_auth` credential unique in its
  namespace.
- **Automation.** Every plugin-config `PUT` or `DELETE` must send
  `expected_proxy_ids`. An `operator` token with an `ns` claim is bounded to
  its namespaces even without `FERRUM_ADMIN_REQUIRE_NAMESPACE_CLAIM`, and may
  not set gateway file paths in plugin configs.

**Foundry changes that need action.**

- **Secrets.** Replace any `replace-me-...` placeholder or documented
  development value in `FERRUM_JWT_SECRET`, `FERRUM_TRUSTED_PROXY_SECRET` or
  `FERRUM_BFF_AUTH_TOKEN`; the BFF no longer starts with one, and there is no
  override.
- **Authentication lockout.** Behind the identity proxy, a proxy that sends a
  wrong secret now locks itself out. Fix the secret and restart the BFF to
  clear it. `FERRUM_AUTH_MAX_FAILURES=0` disables the throttle.
- **HSTS.** A production deployment that serves Foundry, or a subdomain of its
  host, over plain HTTP with Secure cookies left on must set
  `FERRUM_ENABLE_HSTS=false`.
- **Health monitors.** A monitor that read `version` or `components` from a
  health endpoint without a session gets only the verdict.
- **Uploads.** One subject holds at most one of the two default
  restore/API-spec upload permits; static-auth deployments share a single
  subject.
- **Namespace-scoped operators.** They lose TLS inventory, material, ACME,
  event and validation access in Foundry, and cannot change BFF settings.
  Give such an operator a second identity without namespace grants
  ([One identity cannot do both](https://github.com/ferrum-edge/ferrum-foundry/blob/v0.5.6/docs/authentication.md#one-identity-cannot-do-both)).
- **Deployment starter.** Compose does not change an existing network's
  subnet: bring a running starter stack down
  (`docker compose --profile <profile> down`) before the next `up`, and set
  `FOUNDRY_STARTER_SUBNET` if `10.73.88.0/24` overlaps a host network. PKCE is
  on by default; for a provider without PKCE, comment out
  `OAUTH2_PROXY_CODE_CHALLENGE_METHOD` (never use `plain`).
- **Proxies.** A proxy that stored `pool_max_requests_per_connection` loses it
  on its next save from Foundry; the field never had a runtime effect.

### Known limits

Edge's admission stays authoritative: Foundry shows its refusals as returned
rather than refusing locally. On v0.9.20, which lacks ferrum-edge#7393,
credential revocation falls back to re-reading the consumer before deleting.
The Alloy preview refuses the pinned `orders-api.json` fixture until
ferrum-contracts#82 updates it. Existing best-effort and unqualified modes,
eBPF variants, real-gateway scale limits and browser limits are unchanged.

### Publication and deployment

Deploy Foundry v0.5.6 against the paired Ferrum Edge v0.9.20 image above,
pinning the released Foundry multi-architecture index digest listed under
Docker below rather than a mutable tag. Versioned v0.5.5 and earlier notes
and records remain byte-for-byte unchanged; their source, image and CI
evidence are historical, and published version tags never move.
