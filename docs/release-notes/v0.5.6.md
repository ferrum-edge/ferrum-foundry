# Ferrum Foundry v0.5.6

> **Candidate notes.** The unreleased Foundry v0.5.6 candidate pairs with
> published Ferrum Edge v0.9.20 and canonical `contracts-edge-0.9.20` (#686).
> Hosted pairing qualification and Foundry publication are pending; the
> [compatibility record](../compatibility.md) separates candidate evidence
> from published artifacts. The latest published pairing remains v0.5.5 / Edge
> v0.9.15 in its [immutable record](v0.5.5.compatibility.json). Summarize the
> other `[Unreleased]` changelog entries here when the release is prepared.

This candidate moves the development and CI pin from Ferrum Edge v0.9.15 to
published v0.9.20, adopts `contracts-edge-0.9.20`, and aligns Foundry's
plugin templates, guided editors, sensitivity table and `mcp_gateway` mode
handling with the stricter v0.9.19 and v0.9.20 admin contract. It changes no
runtime profile or authority tier.

### Changes since v0.5.5 for the pairing

- **Pin.** Starter, development command and current record use the published
  Edge v0.9.20 digest. Package and lockfile root versions are 0.5.6.
- **Contracts.** The same 18 files are taken byte-exact from
  `contracts-edge-0.9.20`. The plugin catalog keeps its 82 plugins;
  `ai_token_metrics` moves from priority 4100 to 4070, which
  `PLUGIN_PRIORITY` follows.
- **Templates.** Every plugin config is closed in v0.9.19+, and `opa` refuses
  a cleartext host off loopback, so the `opa` template names an `https://`
  OPA host. The other templates keep their v0.9.15 outcomes; the
  `kafka_logging` refusal now names `FERRUM_KAFKA_ALLOWED_BROKERS`.
- **Guided editors.** `rate_limiting` adds `limit_by: service` and
  `max_state_entries`; `cors` adds `allow_private_network` and enforces the
  128-entry bound on its method and header lists; `key_auth` hands an ordered
  list of key locations to the JSON editor instead of flattening it.
- **Secret handling.** The plugin sensitivity table follows Edge's v0.9.20
  projection: `request_transformer` and `mesh_route_dispatch` rule values,
  `response_mock` and `fault_injection` match values, `waf` exemption header
  values and `ws_logging` `custom_headers` are secret, and `ldap_auth`
  `failover_ldap_urls` is an endpoint, so a failed write no longer echoes them.
- **`mcp_gateway`.** The prompt and resource policy keys join the
  aggregate-only keys the editor strips in `transparent_proxy` mode.
- **Demo data.** Seeded API keys meet v0.9.19+'s 16-character floor.

### Upgrading

**Upgrade Ferrum Edge.** Before upgrading Edge from v0.9.15, read its
[Upgrading to 0.9.17](https://github.com/ferrum-edge/ferrum-edge/blob/v0.9.20/docs/upgrade_guide.md#upgrading-to-0917),
[Upgrading to 0.9.19](https://github.com/ferrum-edge/ferrum-edge/blob/v0.9.20/docs/upgrade_guide.md#upgrading-to-0919)
and
[Upgrading to 0.9.20](https://github.com/ferrum-edge/ferrum-edge/blob/v0.9.20/docs/upgrade_guide.md#upgrading-to-0920)
guides; many changes are breaking. Those that affect what you configure
through Foundry:

- **Plugin configs.** Remove unknown keys at any depth, and set
  `allow_plaintext: true` or move to `https://` for an `opa`,
  `serverless_function`, `otel_tracing` or `workload_metrics` endpoint that is
  cleartext off loopback. Edge refuses to save such a config unchanged.
- **Consumer credentials.** Rotate `keyauth` keys shorter than 16
  non-whitespace characters and `jwt` secrets shorter than 32, and make every
  `jwt`, `keyauth`, `basicauth` and `mtls_auth` credential unique in its
  namespace.
- **Automation.** Every plugin-config `PUT` or `DELETE` must send
  `expected_proxy_ids`. An `operator` token with an `ns` claim is bounded to
  its namespaces even without `FERRUM_ADMIN_REQUIRE_NAMESPACE_CLAIM`, and may
  not set gateway file paths in plugin configs.
